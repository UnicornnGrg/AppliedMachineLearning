# AppliedMachineLearning

Branching Strategy

Main Branch (main or master): Only stable, tested code. Never commit directly.
Feature Branches: Create a new branch for each task (e.g., feature/data-cleaning, feature/model-training). Name branches clearly and include your initials or a ticket number if applicable.
Pull Requests (PRs): Always use PRs to merge into main. Assign at least one reviewer. Use PR descriptions to explain changes and link to relevant issues.

Commit Messages

Use clear, descriptive messages (e.g., "Add data cleaning script for missing values").
Follow the Conventional Commits format if possible.

Avoiding Merge Conflicts

Pull Often: Before starting work, pull the latest changes from main to your feature branch.
Small, Frequent Commits: Commit small, logical changes frequently.
Communicate: Let your team know if you’re working on a shared file.
